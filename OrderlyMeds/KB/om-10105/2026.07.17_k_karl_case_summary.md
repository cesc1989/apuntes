# Caso: orden de k_karl@hotmail.com no aparecía en el portal

## Síntoma reportado

La clienta reportó que su primera y única orden (colocada ~6/24... aunque el
`effective_date` real de la orden en Salesforce es 2026-06-04) no aparecía en
su portal de paciente. Un agente de soporte impersonó la cuenta y confirmó que,
efectivamente, no se veía ninguna orden.

## Hipótesis descartadas

### 1. Cuenta duplicada / fusión de cuentas pendiente (mi primera sugerencia)

La primera hipótesis fue que la migración Ontraport → Salesforce había dejado
una **cuenta duplicada** en Salesforce (`Salesforce::PersonAccount`), con la
orden colgando de un `omid` distinto al que usa hoy el portal
(`accounts.salesforce_account_nk`). Este es un patrón real y conocido en esta
base de código — existe todo un subsistema (`AccountMerge`,
`app/models/account_merge.rb`, `app/services/account_merge/*`) para reparentar
`Salesforce::Order`/`OrderSummary` de una cuenta perdedora a una sobreviviente.

**Se descartó con datos:** solo existía una `Salesforce::PersonAccount` para
ese email, sin `AccountMerge` pendiente, y la `Order`/`OrderSummary` ya
apuntaban (`account__omid__c`) a la cuenta correcta. No era un problema de
cuenta duplicada.

### 2. Reenlazar la orden a un `MemberPeriod` distinto (segunda hipótesis, también incorrecta)

Al investigar más profundo, la orden estaba enlazada
(`memberperiodid__r__omid__c`) a un `Salesforce::MemberPeriod` con
`status = "ImportedFromOntraport"`. Encontré que
`Patient::Connectors::Salesforce::Script#is_a_valid_order?` trata cualquier
orden cuyo member period esté en ese estado como "legado", exigiendo que su
`outcome` sea `"Shipped"` para mostrarse — y como no lo era, la orden se
filtraba de la lista.

Propuse reenlazar la orden a otro `MemberPeriod` de la cuenta que parecía más
plausible por coincidencia de timestamps (creado en el mismo segundo que la
orden). **Esto era incorrecto**, y el usuario lo objetó correctamente: ese
otro member period no tenía ninguna relación real con esta orden.

### Confirmación con Ontraport: solo existían 2 scripts reales

La clienta reportó (verificado en vivo contra Ontraport vía
`Ontraport::Meta::Script.get_by_contact_id`) que solo tenía **dos scripts**:

| Ontraport script | outcome | notas |
|---|---|---|
| `637613` | `Delivered` | `master_id = C03608AB-1D8E-49C9-83EC-F2139A0E7CAB` — coincide exactamente con el `order_reference_nk` de la orden nativa |
| `902481` | `Check-In` | `check_in_script? = true`, sin `master_id` (no es una orden) |

Cruzando esto contra los 3 `Salesforce::MemberPeriod` locales de la cuenta:

- `MemberPeriod` con `ontraport_script_id = 637613` → **es el mismo al que la
  orden ya estaba enlazada**. El `order_number` del `OrderSummary` (`637613`)
  ya coincidía con este script desde el primer diagnóstico — la evidencia
  estaba ahí desde el inicio.
- `MemberPeriod` con `ontraport_script_id = 902481` → corresponde al script de
  Check-In, sin ninguna orden asociada.
- El tercer `MemberPeriod` (`CheckinDelayed`, sin `ontraport_script_id`) es un
  ciclo nativo de Salesforce — la continuación viva del script de Check-In, sin
  relación con la orden. Este era el que yo había propuesto usar para el
  reenlace — un error.

**Conclusión:** la orden siempre estuvo enlazada al `MemberPeriod` correcto. El
reenlace nunca era necesario ni correcto.

## Causa raíz real

El importador de la migración (`lib/ontraport_migration/member_period_mapping.rb`)
copió correctamente el outcome `"Check-In"` al `MemberPeriod` del script
`902481`, pero **falló en copiar `"Delivered"`** al `MemberPeriod` del script
`637613` — el campo `ontraport_imported_outcome` (columna
`ontraportimportedoutcome__c`) quedó en `nil` en vez de `"Delivered"`.

Este campo es un snapshot de solo-escritura-una-vez, tomado en el momento de
la migración; nunca se vuelve a actualizar después.

### El código involucrado

**`Patient::Connectors::Salesforce::Script#is_a_valid_order?`**
(`app/models/patient/connectors/salesforce/script.rb:109-115`)

```ruby
def is_a_valid_order?
  if imported_from_ontraport?
    valid_shipped_order_from_ontraport?
  else
    true
  end
end
```

Con `imported_from_ontraport?` delegado al `member_period.status ==
"ImportedFromOntraport"`, y `valid_shipped_order_from_ontraport?`
(`script.rb:141-143`) exigiendo `outcome == "Shipped"`.

**`Patient::Connectors::Salesforce::Script#outcome`** (`script.rb:42-45`):

```ruby
def outcome
  return nil unless member_period
  @outcome ||= Patient::Connectors::Salesforce::OrderStatus.new(
    member_period_status: member_period.status,
    ontraport_outcome: member_period.ontraport_imported_outcome
  ).get_outcome
end
```

**`Patient::Connectors::Salesforce::OrderStatus#get_outcome`**
(`app/models/patient/connectors/salesforce/order_status.rb:83-98`):

```ruby
def get_outcome
  outcome = Patient::Connectors::Ontraport::OrderStatus.new(outcome: ontraport_outcome).name if ontraport_outcome.present?
  if outcome
    return "Shipped" if SHIPPED_ONTRAPORT_OUTCOMES.include?(outcome)
    return "Processing" if PROCESSING_ONTRAPORT_OUTCOMES.include?(outcome)

    "Canceled" if CANCELED_ONTRAPORT_OUTCOMES.include?(outcome)
  else
    return "Delivered" if DELIVERED_SALESFORCE_STATUSES.include?(member_period_status)
    return "Shipped" if SHIPPED_SALESFORCE_STATUSES.include?(member_period_status)
    return "Processing" if PROCESSING_SALESFORCE_STATUSES.include?(member_period_status)
    return "Medical Review" if REVIEW_SALESFORCE_STATUSES.include?(member_period_status)

    member_period_status
  end
end
```

Con `ontraport_imported_outcome = nil`, la primera línea nunca entra al `if
outcome`, y cae al `else`, que termina devolviendo el `member_period_status`
tal cual (`"ImportedFromOntraport"`) porque ese status no está en ninguna de
las listas `*_SALESFORCE_STATUSES`. Como `"ImportedFromOntraport" !=
"Shipped"`, `is_a_valid_order?` daba `false`.

Con el fix (`ontraport_imported_outcome = "Delivered"`), `ontraport_outcome.present?`
es `true`, se resuelve vía `Patient::Connectors::Ontraport::OrderStatus#name`
al símbolo `:medication_delivered`, que sí está en `SHIPPED_ONTRAPORT_OUTCOMES`
→ `get_outcome` devuelve `"Shipped"` → `is_a_valid_order?` da `true`.

## Cadena completa: vista → `is_a_valid_order?`

La clienta usa la vista v1 (`_v1_order.html.erb`), así que este es el camino
recorrido:

```
app/views/patient/orders/v1_index.html.erb:8-15
  <% orders.each do |order| %> ... render partial: "v1_order", locals: { order:, dashboard: }

  → app/controllers/patient/orders_controller.rb:20-22   #v1_index
      render :v1_index, locals: { orders:, dashboard:, ... }

    → orders_controller.rb:68-70   #orders
        @orders = connector.orders

      → app/models/patient/connectors/salesforce/base_connector.rb:16-18   #orders
          def orders
            scripts.select { it.is_a_valid_order? }
          end

        → base_connector.rb:66-76   #scripts
            salesforce_account.order_summaries...map { Script.new(order_summary: it) }

          → app/models/patient/connectors/salesforce/script.rb:109-115   #is_a_valid_order?
              → script.rb:141-143   #valid_shipped_order_from_ontraport?  (outcome == "Shipped")
                → script.rb:42-45   #outcome
                  → app/models/patient/connectors/salesforce/order_status.rb:83-98
                      Patient::Connectors::Salesforce::OrderStatus#get_outcome
                    ← lee member_period.ontraport_imported_outcome
                        (alias de ontraportimportedoutcome__c,
                         app/models/salesforce/member_period.rb:265)

app/views/patient/orders/_v1_order.html.erb:30
  <%= render "patient/orders/status/#{order.status}", order: order %>
  → usa Script#status (script.rb:47-50), que llama a OrderStatus#name
    con el mismo ontraport_imported_outcome como input
```

Es decir: la vista `_v1_order.html.erb` ni siquiera llega a renderizarse para
esta orden mientras `is_a_valid_order?` sea `false` — el filtro ocurre antes,
en el controller (`orders_controller.rb:68-70` → `base_connector.rb:16-18`),
así que la orden desaparece de la colección `orders` completa, no solo de un
detalle visual dentro de la vista.

## Fix aplicado

Un solo `update!` sobre el `Salesforce::MemberPeriod` correcto (el que ya
estaba bien enlazado a la orden), corrigiendo el campo de snapshot faltante:

```ruby
mp.update!(ontraport_imported_outcome: "Delivered")
```

Ejecutado vía `~/Downloads/om-cases/2026.07.17_k_karl_fix_member_period_outcome.rb`
en producción. Confirmado: la orden ya aparece en el portal.

## Nota para seguimiento (no resuelto aquí)

El importador de la migración parece tener un bug que puede dejar
`ontraport_imported_outcome` en `nil` para ciertos scripts migrados (funcionó
para el script "Check-In" pero falló para el "Delivered" de esta misma
cuenta). Vale la pena revisar `lib/ontraport_migration/member_period_mapping.rb`
para ver si otras cuentas migradas tienen el mismo hueco — eso ya sería un
ticket aparte, no algo que se resolvió en este caso puntual.
